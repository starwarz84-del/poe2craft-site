## 2. 다른 팀원과 나눈 범위

같은 저장소를 다른 세션이 함께 고쳐요. 겹치지 않게 지켜요.

| 담당 | 범위 | 도과장이 할 것 |
|---|---|---|
| 마스터 에이전트(`docs/master-agent.md`) | 아이템별 레시피·플로우차트를 영상 기준으로 처음부터 다시 만듦. `scripts/graphs/`, `gen_batch*.py`, `scripts/graph2recipe.py`, `site/data/sim/`, `docs/fc-review.md`, 레시피 정의 파일 | 건드리지 않음. 공용 코드 문제를 부탁받으면 그 부분만 고침 |
| 도과장(이 문서) | 위 1장 전부 | 마스터 작업물과 겹치는 파일을 고칠 땐 커밋 메시지에 이유를 적음 |

- 커밋 메시지가 `작업 중(검수 전)`인 다른 세션의 변경은 **배포하지 않아요**. 마스터가 `검수 완료`를 남기고 release를 돌린 뒤에 나가요.
- 그래서 도과장이 자기 변경만 내보낼 때는 배포 폴더 전체를 다시 만들지 않고, 바뀐 원본의 diff만 `web/`의 같은 파일에 적용해요.

```
git diff site/recipes.html > /tmp/my.patch
sed 's#site/recipes.html#web/recipes.html#g' /tmp/my.patch | git apply --recount
```

  적용한 뒤 `web/`을 8790 포트로 띄워 화면을 캡처해 확인하고 그 파일만 커밋해요. 남의 검수 전 변경이 없을 때(`git log`에 `작업 중` 커밋이 release 이후 없을 때)는 평소처럼 `bash tools/release.sh` 전체를 돌려요.
- 푸시 전에는 늘 `git pull --rebase`를 해요. 생성 파일이 충돌하면 `git checkout --ours`로 받고 다시 빌드한 뒤 `<<<<<<<` 표시와 JSON이 깨지지 않았는지 확인해요.

## 7. 오늘 겪은 함정(같은 실수 막기)

- `recipes.html`에서 `[data-tip]`은 오른쪽 아이템 카드 자리, `[data-tipid]`는 커서를 따라가는 툴팁(`.ctip`)이 이미 써요. 새 요소엔 겹치지 않는 이름을 써요(단계 꿀팁은 `data-tipkey`).
- 단계 안 요소는 `.nbody` 그리드(3칸) 안에 들어가요. 가로 전체를 쓰려면 `grid-column:2/4`를 줘요.
- 꿀팁의 `recipes`에 적힌 레시피 id는 옛 이름(-v2 없음)이에요. 화면에서는 `tipRecipes()`가 -v2·등급판으로 찾아요.
- `site/*.html`엔 줄 끝 `//` 주석 금지(한 줄에 문장이 여러 개라 뒤 코드가 가려짐). `/* */`를 써요.
- 게시된 사이트는 샌드박스 iframe이라 `confirm()`·`alert()`가 막혀요. 확인은 '한 번 더 누르기'로.
- Playwright에서 같은 페이지에 `#해시`만 바꿔 `goto`하면 다시 읽지 않아요. 주소에 `&x=<id>` 같은 값을 붙여요.
- 긴 검사를 두 개 동시에 돌리면 테스트 서버가 느려져 부팅 대기가 30초를 넘겨요. 하나씩 돌려요.
